# v16 학습 콘텐츠 분리 연결

운영 데이터의 SPREADSHEET_ID는 변경하지 않습니다. 학생·저장·공개 상태·로그·TranslationProgress는 운영 파일을 계속 사용합니다.

콘텐츠 파일은 별도 CONTENT_SPREADSHEET_ID로 연결합니다. setupLearningContentV16 함수가 전달받은 콘텐츠 파일에 대한 접근과 37개 데이터 탭의 필수 열을 검사합니다. 설정된 속성으로 연결을 검증합니다. 콘텐츠를 덮어쓰거나 기존 TranslationQuestions를 삭제하지 않습니다.

## 적용 순서

1. 기존 Apps Script 프로젝트에서 전체 코드를 Code_v16.gs로 교체합니다. 모듈 파일을 추가로 설치하지 않습니다.
2. 프로젝트 설정의 스크립트 속성 CONTENT_SPREADSHEET_ID에 학습 콘텐츠 파일 ID를 설정한 뒤 setupLearningContentV16을 실행합니다. 실행 계정에 이 파일의 읽기 권한이 있어야 합니다. 공유는 제한됨을 유지합니다.
3. v14 속도 개선 설정을 아직 하지 않았다면 setupTranslationPerformanceV14를 한 번 실행합니다.
4. 기존 웹 앱 배포를 새 버전으로 업데이트합니다. 기존 URL을 유지하면 게임 코드의 주소를 바꿀 필요가 없습니다. 새 URL을 만들면 게임에도 새 주소를 연결해야 합니다.
5. 게임을 새로고침합니다. 서버 apiVersion 16 확인 후 콘텐츠 시트 조회 UI가 활성화됩니다. v15까지는 기존 일반 퀴즈/실험 화면을 유지합니다.

## 읽는 탭

- Tutorial: legacyQuestId 0, 1, 2로 튜토리얼 순서를 연결합니다.
- Quiz_01~Quiz_12: 각 스테이지에서 active인 문제 중 하나를 추출합니다. 완료 후 복습도 해당 탭을 사용합니다. 각 스테이지의 완료·보상은 기존대로 한 번만 적용됩니다. question, 보기, explanation, rewardDose, rewardCoins, title을 읽습니다. 퀘스트 목록/관문 제목은 게임 메타데이터를 유지합니다.
- Translation_01: Stage 1 번역 퀴즈의 문제은행입니다. 5문제 출제, 서버 판정, 원본 Students 저장과 비동기 집계는 유지합니다. 운영 파일의 TranslationQuestions는 이제 읽지 않습니다.
- Translation_02~12: 구조를 검증합니다. 해당 스테이지 번역 PC 기능은 기존에 없으므로 새로 만들지 않습니다.
- Experiment_07: 기존 MOSFET 공정 과제의 문구와 순서를 읽습니다. 기존 6개 stepId와 sequence 형식을 유지해야 합니다. 도식과 MOSFET 동작 시각화는 게임 코드가 담당합니다. 기존처럼 완료 기록만 저장하며 실험 rewardDose/rewardCoins는 사용하지 않습니다.
- 다른 Experiment 탭: 구조를 검증합니다. 새 실험 유형의 화면은 별도 구현이 필요합니다.
- 낡은 책: 콘텐츠 파일에 본문 탭이 없으므로 기존 코드 내용을 유지합니다.

## 편집과 캐시

내용은 서버에서 60초간 캐시합니다. 즉시 반영하려면 clearLearningContentCache를 실행하고 문제를 다시 여세요. 시작된 문제는 스냅샷으로 판정하므로 편집 중 정답이 바뀌지 않습니다. 일반 퀴즈·실험 스냅샷은 최대 30분간 서버 캐시에 저장되며 조기 퇴거 시 다시 열기 안내를 표시합니다. 번역 회차는 기존처럼 Students에 저장됩니다.

API는 로그인 토큰을 검증하고 현재 스테이지에서만 문제를 준비합니다. 일반 퀴즈·실험 응답에는 제출 전 정답/정답 순서를 포함하지 않습니다. 일반 퀴즈·실험의 보상/완료 저장은 기존 게임 저장 흐름을 유지합니다. 전체 게임 저장을 서버 권위 방식으로 전환하거나 과거/기존 코드의 문제은행을 제거한 작업은 아닙니다.

## 검증

서버 단위 테스트는 두 파일 분리, 열 재배치, 캐시/편집 반영, 비활성/중복 문제, 학생별 스냅샷, 정답 비공개, 실험 판정, 설정 실패 복원을 확인합니다. 첨부된 기존 콘텐츠 XLSX 구조도 검증합니다. 제한된 실제 Google Sheet 접근 및 라이브 게임 풀이 검증은 사용자 계정에서 설정·배포 후 필요합니다.
